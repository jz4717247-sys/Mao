# 质量门槛

评分用于发现薄弱层级，不用于把审美伪装成数学。每项采用 0–3：

- **0 缺失**：核心功能不存在或自相矛盾。
- **1 不稳**：意图可见，但需要观众替文本补足。
- **2 成立**：功能清楚，只有局部问题。
- **3 强**：功能清楚、有角色特异性，并推动后续。

## 开发稿评分

| 维度 | 核心问题 |
|---|---|
| Premise | 主角、压力系统、选择与代价是否具体 |
| Series Engine | 是否能产生多个不重复且只属于本剧的故事 |
| Pilot Promise | Pilot 是否演示未来剧集，而非只交代前史 |
| Ensemble | 主要人物是否拥有独立欲望和相互冲突的杠杆 |
| Season Question | 季问题是否可追踪、可升级、可在季终改变状态 |
| Tone / Genre | 类型满足与项目独特语调是否同时存在 |

## Episode / Script 评分

| 维度 | 核心问题 |
|---|---|
| Episode Motion | 开场状态到结尾状态是否发生明确变化 |
| Causality | 转折是否主要来自角色选择与后果 |
| Escalation | 代价是否变得更具体，而非只变得更吵 |
| Character | 行动是否来自欲望、盲点、关系和当下知识 |
| Voice | 角色是否可区分且允许压力变化 |
| Dialogue | 信息、潜台词与直接表达是否各有功能 |
| Continuity | 时间、知识、状态、规则与线索是否一致 |
| Ending | 是否完成本集动作并制造新的不稳定状态 |
| Producibility | 仅在任务相关时，成本与戏剧价值是否相称 |

## Go / No-Go

出现以下任一情况，通常不得进入精细对白稿：

- Series Engine 尚不能产生多个不同故事。
- 主角不做关键选择，故事主要靠巧合推动。
- 核心人物知道不该知道的信息。
- 世界规则为了单场方便临时改变。
- 主要故事线结尾与开场状态相同且无意为之。

若低分来自明确的实验性选择，说明选择和代价，不要自动“修正”成传统结构。
