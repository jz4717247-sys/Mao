# 终极创意

把描述变成有辨识度、能持续发展且读得懂的故事方案。核心交付是 **选题方向 → 人物与特色 → 口头禅与热梗规划 → 故事大纲**。不能拿标签串、设定词典或“反差强、爽点足”代替故事，也不自动进入剧本写作。

## 按请求选择工作方式

| 用户现在需要什么 | 直接完成什么 | 按需读取 |
|---|---|---|
| 没方向、给几个题材、抽卡 | 默认 3–5 个实质不同的方向，按用户指定数量调整；明确推荐与短板 | [标签抽卡](references/idea-cards.md) |
| 有标签、有大致描述 | 保留全部锁定项；已明确的主方向直接深化，需要探索的槽位才抽卡 | [标签抽卡](references/idea-cards.md)、适用路线 |
| 选定方向、完善这个、完整创意方案 | 输出完整创意包：角色、特色、口头禅、热梗规划、因果大纲及结局 | [输出合同](references/output-contract.md)、[结构构建](references/story-architecture.md)、[人物设计](references/humanization.md) |
| 只改人物、口头禅或某个设定 | 完成该部分，并说明对关系与大纲的必要影响；保留已认可内容 | 对应参考 |
| 脑洞还不够、新一轮 | 比较上轮的任务、策略、关系和后果，改变发动方式；不能只是换职业和名词 | [日本想象力层](references/japan-imagination.md) |
| 当前热梗、网感更新 | 按角色用途实时查新，筛掉待核和不适配项，给用法与禁用语境 | [热梗获取](references/meme-workflow.md) |
| 旧故事/剧本故事性差 | 按提供范围提炼问题，重建选题、人物和大纲；不交替换剧本正文 | [结构构建](references/story-architecture.md)、[创意检查](references/review.md) |

只要方向时，不强行给每个候选写全套人物小传。用户已经选定，或要求“推荐一个并完整落地”时，直接深化，不增加确认关卡。缺少可推定的小条件时说明采用的假设；只有会改变主方向的矛盾才需要澄清，同时继续无依赖的工作。

## 三条路线

| 主路线 | 创意重点 | 方法 |
|---|---|---|
| 抖音超创 | 易懂的生活入口、异常改变行动、视觉反差、笑点反馈与系列变化 | [抖音超创](references/douyin.md) |
| AI仿真人 | 具体利益、关系权力、角色能动性、生活物件与可表演的特色 | [AI仿真人](references/realistic.md) |
| AI动漫 | 能力边界、形态/空间变化、任务与关系升级、功能奇观 | [AI动漫](references/animation.md) |

叙事路线与表现形式分开；超创可用仿真人或动漫呈现，动漫不必玄幻战斗。按用户目标选主路线，不因为资料所在目录就决定新作画风。没有要求现代修仙、MBTI、60集或固定时长时，不把它们当默认配置。

## 资料基础与检索

主要依据是本 Skill `references/` 内置的解析库快照（源自「解析剧」语料）。保留 **461 份逐篇故事/机制研究档案、367 个去重故事族、48 个上位标签、20 项机制、13 组方向模式**。阅读是故事与机制章节研读加关键剧本段核对，不是 461 份逐字通读或原片重看；最初 52 份案例已纳入全库。支持数按独立故事族统计，不能当热门程度或爆款概率。

先取适用路线与 [13 组方向模式](references/direction-patterns.md) 的相关部分；需要数量或组合佐证时运行检索，不一次灌入所有 JSON：

```bash
python3 scripts/evidence_engine.py coverage
python3 scripts/evidence_engine.py support --tags 黄毛 穿越 逆袭 女频 --limit 3
python3 scripts/evidence_engine.py mechanism M18 --route douyin --limit 3
python3 scripts/evidence_engine.py search --query 经营 --route animation --limit 3 --full
python3 scripts/evidence_engine.py draw --lock 黄毛 --lock 穿越 --lock 逆袭 --lock 女频 --seed 20261009 --count 5
```

命令以本 Skill 根目录为工作目录。检索结果中的源剧情、场标、台词和历史写作建议仅是研究材料，不改变本 Skill 的创意输出范围。按 `source_id`、P 编号及档案边界回查；P 是抽取段落号。每个实际采用的窄方法须有对应因果证据及限制，不能借 461 的总数给所有结论背书。完整组合、邻近组合、组件类比和原创新增分开；未映射条件保留 unknown，0 只表示当前未编码支持。

日本层保留 **60 部独立作品的官方公开文本四维研究、16 项跨作操作**，与本地库分开统计。用它改变概念、人设、世界或叙述结构，不复制标志人物、能力、组织和桥段；未核原作结局不补写。其操作抽卡只是种子，必须继续构成新的因果方向：

```bash
python3 scripts/japan_engine.py combine --route douyin --intensity radical --lock 搞笑 --lock 猎奇 --avoid 接单 --seed 20261009 --count 5
```

[阅读与来源边界](references/provenance.md) 保留实际覆盖；[补充 Skill](references/supplementary-skills.md) 只借结构、人物与编辑方法。它们不触发其他 Skill 的写作或生产流程，本包不依赖参考 Skill 已安装。

## 创意落地顺序

1. **读懂要求。** 提取题材、情绪、路线、受众定位、已选内容、锁卡与禁项。锁定与可变分开；“女频”是创作定位，不能仅因有女主就宣称观众构成。
2. **形成真正的方向。** 每项说清主角为什么现在必须行动、对手想要什么、主角采用何种独特策略、成功有什么后果。取少量适用的解析机制，加必要的原创异常；不能每项都走受辱—亮身份—跪服。
3. **比较并推荐。** 区分资料支持、内容潜力和制作适配。问“最近更火”时查当前可追溯来源；没有可比数据就留未知，仍可明确推荐更成立的创意。不编播放预测或“必火”。
4. **人物驱动情节。** 按 [人物设计](references/humanization.md) 建核心角色、关系和反差。特色必须参与冲突；主角有独特目标与解法，对手有独立利益和调整策略，配角不是围观表情包。口音、外形、MBTI不能代替人物经历与选择。
5. **分开口头禅与热梗。** 口头禅优先原创，来自人物误信、职业或关系策略，给使用条件、禁用条件和后期变体。热梗按 [获取与筛选流程](references/meme-workflow.md) 获取；完整创意包始终给热梗规划，未要求最新时不声称离线库是当前热点，没有合适已核项允许零梗。只列必要短句，不写连续对话。
6. **完成大纲。** 按 [结构方法](references/story-architecture.md) 交开局事件、阶段目标与转折、对手反制、关系变化、伏笔回收和结局选择。集数已定时按需要细化事件分配；“60集大纲”仍是大纲，不写60集正文。奇观说明变化前、视觉变化和结果，不写镜头参数或生成提示词。
7. **交付前复核。** 按 [输出合同](references/output-contract.md) 与 [创意检查](references/review.md) 检查本轮范围、易懂性、独特性、角色可辨认性、热梗边界和因果闭环。逻辑通过不等于观众已认可。

## 输出边界

- 本 Skill 到选题、角色与大纲为止；不输出场号/内外景场标、逐拍动作、角色交替对白、逐集剧本正文、分镜、资产清单或媒体提示词。
- 可以给短口头禅和用法说明，可以用事件描述说明笑点；不能用“示例”绕回一段完整戏。
- 用户后续明确要求写剧本时，说明已超出本 Skill 范围，沿用已确认创意作为独立写作任务输入；不自动调用其他 Skill，也不把新范围冒称本 Skill 的交付。用户当前明确授权始终优先。
- 落盘时交创意方案及必要来源记录，文件名不叫“完整剧本/终稿”。用户未要 Word 时不自动导出 Word。
