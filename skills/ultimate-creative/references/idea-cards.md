终极创意的选题流程只输出方向与事件规划，不生成分场或对白正文。源解析中出现的正文/场面证据保留为研究材料。

# 标签抽卡与剧目方向判断

先把“想看什么”变成具体观众承诺，再组合设定。用户要的抽卡是一种创意探索方法；不能靠随机拼词代替故事。

## 一 标签拆成不同职责

| 槽位 | 例子 | 必须回答 |
|---|---|---|
| 受众与情绪承诺 | 女频、男频、关系拉扯、尊严夺回、经营满足 | 谁的欲望居中，观众等待哪种兑现？男/女频是创作定位，非实测受众性别 |
| 主角身份/外在标签 | 黄毛、失业父亲、机修师、祖母、被低估的配角 | 身份怎样改变能力、偏见、社会关系和解题方式？ |
| 起始处境 | 被利用、背债、失去工作、资源枯竭、被安排的人生 | 眼前必须解决什么，拖延会失去什么？ |
| 世界触发 | 穿越、重生、系统、灵魂互换、规则入侵 | 哪条已知生活规则被改变？主角知道多少？ |
| 关系 | 临时同盟、互相利用、竞争搭档、照护者与被照护者 | 两人有什么共同目标和无法兼得的利益？ |
| 主冲突/任务 | 争回学籍、保住小店、护送、查证、重建信任 | 能持续产生具体行动，还是只有抽象标签？ |
| 回报 | 逆袭、真相揭露、被看见、互相选择、团聚、规则反杀 | 第一集和后续分别兑现什么？ |
| 代价/限制 | 使用次数、暴露身份、失去信任、资源消耗 | 为什么能力不能立即解决所有问题？ |
| 表现方法 | 微表演、道具证据、尺度变化、能力状态、空间规则 | 为何适合这一条制作路线？ |

槽位用于思考，不要求每个候选标题堆9个标签。对外通常保留4–6个有区分度的核心标签；其余转为故事细节。对同一维度的“穿越＋重生”等组合，解释二者各自新增的必要功能；解释不清就删一个或列为替代卡，不能制造设定噪声。

标签卡来源：

1. [tag-cards.json](tag-cards.json)：按具体正文整理的样本卡，附段落和“观察/归纳”标注。优先使用。
2. [corpus-catalog.json](corpus-catalog.json)：461份资料对应的台账标签、历史热度和文件身份，适合找候选文档；标签尚不代表逐段核验。
3. 用户自带卡：完整保留，标记 `user_supplied`，不虚构语料来源。黄毛、女频等若样本没有明确支持，可作为用户创作约束，不能反推样本受众。
4. 原创增补卡：标记 `creative_extension`，说明借了哪种机制及新增部分，不伪装为资料结论。

## 全库证据先行

本版461份均有逐篇档案。先看 [13组跨故事方向模式](direction-patterns.md)：每组含3–4个具名独立故事的因果类比、边界和原创迁移示范。模式案例数与完整标签组合支持数分开报告。做方向判断时，先查当前路线中相关标签和机制的**独立故事支持数**，至少读几个不同故事的因果及限制，再选创意。支持名单可以逐条回查，不能只报“研究了很多”。以下命令在Skill根目录运行，无网络、无写入、无收费调用：

```bash
python3 scripts/evidence_engine.py coverage
python3 scripts/evidence_engine.py support --tags 穿越 系统 --route animation --limit 3
python3 scripts/evidence_engine.py support --tags 黄毛 穿越 逆袭 女频 --limit 3
python3 scripts/evidence_engine.py mechanism M06 --route realistic --limit 3
python3 scripts/evidence_engine.py search --query 经营 --route animation --limit 3 --full
python3 scripts/evidence_engine.py market --tags 系统 --board comic --date 2026-10-02
python3 scripts/evidence_engine.py draw --lock 黄毛 --lock 穿越 --lock 逆袭 --lock 女频 --seed 20261003 --count 5
```

`support`同时给单项、两两和完整组合。完整组合必须在同一档案中共同被编码，再按故事族去重；不把不同季的不同标签硬凑在一起。`女频`等无法用正文客观确认的约束会留作未映射项，使完整组合数量为unknown；已映射部分单列，不能代替完整组合。

上位类名称有意较宽，例如“低位与逆袭处境”“灵魂与身体错位”。传入`T23`或完整上位类名会查询整个类别；传入具体别名`逆袭`还要求原始语义标签含该词，不能把仅“被低估”的案例算成逆袭。映射与范围在`tag_resolution`明示；同义措辞可能漏检，必要时用`search --full`阅读原卡，不能据零结果断言源库没有。即便标签写逆袭，也需读M08和限制判断它在已解析范围是否兑现。

`draw`只产可回放的创意种子：先均匀抽故事族，再从适合槽位的标签抽取，续季多的故事不会因此更容易中。它不预测市场、不直接交付新剧方向。必须继续补因果、开局事件概述、初期三次兑现，修复冲突并保留锁卡，再按本文件格式交付。没有要求随机时可有意识地选不同策略，不用随机装饰替代判断。

推荐排序的证据分四层记录：`完整组合 n 个独立故事 / 邻近组合 n 个 / 各组件 n 个 / 原创新增`。没有完整组合支持的方向仍可优先深化，但理由要来自新因果与可验证兑现，不伪称组合已被市场验证。不同组合的支持数不相加，不把20码中某机制的高支持量转嫁给一条窄技巧。

完整支持名单和逐字证据在 [full-dossiers.json](full-dossiers.json)，全库方法见 [mechanism-atlas.md](mechanism-atlas.md)。初始细节案例仅作场景讲解，跨案例结论以统一编码重新核查。

无需一次加载整个库。可先读取 [tag-index.json](tag-index.json) 中相关维度，或在 Skill 根目录运行只读检索：

```bash
python3 scripts/query_library.py --kind cards --query 黄毛 --limit 3 --full
python3 scripts/query_library.py --kind cards --route animation --query 经营 --limit 5
python3 scripts/query_library.py --kind catalog --query 穿越 --limit 5
python3 scripts/query_library.py --kind evidence --source-id Sc708478c40 --limit 10
```

脚本是字面检索，多词表示同时包含；无结果时换同义词或逐维度查，不能报告全库不存在该机制。目录排序不是推荐顺序。正式采用前读卡的证据与限制；`--full` 会显示完整来源边界。

## 二 四种抽卡方式

**没有方向。** 优先根据用户当前想做的路线、已有题材或资源抽；都没有时可给跨三路线的5个方向，注明不同制作形式，先形成可比较结果。候选配置建议：2个熟悉欲望+新解法、2个身份/关系反差、1个新规则探索。不是固定市场配比。

**锁定部分方向。** 先列 `锁定卡` 与 `可抽槽位`。核心不改，补1–2张改变戏剧结构的卡。用户锁4项时，不再无边界叠加末世、系统、豪门、重生、萌宝；用具体职业、利益关系和行动代价把4项连起来。

**已有成熟方向。** 不重抽主命题。只扩未定维度或直接落地完整创意包；用户要推荐并落地时选择适配方案继续，不增加未要求的审批关卡。写剧本正文属于独立任务，不在本 Skill 内自动启动。

**重抽或换卡。** 保存当前候选编号及用户认可项；换卡应改变矛盾/策略/关系，而非只换地名和名字。用户说“不要爽剧”就移除爽剧承诺，不能仅把“逆袭”改名为“成长”。

每轮用 `C01…C05` 编号，记录本轮约束、锁定卡、排除卡、补充卡及来源ID。无需伪造随机概率或“稀有度”；用户要求真正随机、种子或可回放时，才运行可复现的随机采样并记录候选池、种子及筛选原因。

## 二补充 想象力重构与跨作品抽卡

用户要求更大胆或日本作品方法时，读 [日本想象力层](japan-imagination.md)。本地标签卡负责用户定位与成熟场面机制，日本公开文本研究负责补充概念、人物、规则和结构的操作。二者分库计数；不要称为“521份全片解析”。

从不同独立作品借2个不同职责的操作，例如“资源来源改写”与“搭档利益相撞”，再由当前人物目标和代价连成新因果。`japan_engine.py combine`保存锁卡、来源、操作和随机种子，但不写完整方向；必须继续写开局事件概述与三次不同发展/兑现，不扩成完整场面。原样交脚本卡片仍是不合格。

用户连续说“不够脑洞”时，比较前轮的发动方式：若持续是怪物日常、开店经营或单个身体梗，新一轮优先改变任务目标、关系权力、时间组织或信息分配，给出不同因果的方向。不强迫所有作品扩大到宇宙尺度；大胆可以发生在一句承诺、一种关系或一次无法撤销的选择中。

抽卡包含两类内容：故事素材（身份/关系/世界/任务）与结构操作（怎样误信、隐藏、重复、付代价和兑现）。不能仅靠增加素材词数量来提高原创程度。用 [完整构建方法](story-architecture.md) 完成人设网络、可验证规则和阶段结构。

## 三 组合先过因果检查

把候选压成一句：

`一个【身份】因【触发】陷入【具体处境】，为【目标】必须与【关系人物】以【独有策略】对抗【阻力】，每次成功都会【代价/新后果】。`

依次检查：

- **身份有效**：换成任意普通人，故事是否一样？一样则身份还没发挥作用。
- **触发有效**：去掉穿越/系统，关键行动是否仍相同？相同则只是噱头。
- **定位一致**：谁在作选择、谁获得兑现？“女频”不能只靠出现女主，“黄毛”也不自动等于反派或性格恶劣。
- **冲突可连载**：至少能自然产生3次不同任务/对手策略/关系选择，不是复读三次打脸。
- **能力有边界**：成功由之前建立的能力和选择产生，不能临场赠送万能权限。
- **有新因果**：至少在目标、规则、关系、高潮代价上形成实质差异，不能只换原解析作品的名字或物件。
- **表达适配**：超创侧重异常与生活的可理解反差；仿真人侧重可表演关系；动漫允许显性的规则状态与形变。可混合，但须明确主叙事路线。

不兼容先给修复方式，例如“保留穿越，把全知改为只知道前一晚的信息”；不要默默删锁卡。若用户约束确实无法同时成立，明确指出具体冲突并提出最小替换。

## 四 哪个方向更可能受欢迎

结论分为三列，不合成一个伪客观的“爆率”。

### 市场证据

- **已核近期数据**：同平台、同榜单类型、同窗口、可追溯来源，注明获取时间和指标定义。热度不等于播放量，播放也不等于完播或付费转化。
- **历史资料快照**：本地台账保存了排名、热度与日期，但没有因此重新核验平台。可描述历史样本表现，不直接声称当前流行。
- **无可比数据**：保留未知。抖音样本缺标签或热度不代表没人看；未收录失败作品也不能推断成功率。

用户问“现在/最近更火”或要求当前市场比较时，查当下可访问的官方榜单/公开平台来源；无法取得就说明缺口，并继续给内容层判断。无需为普通抽卡强制联网。引用只支持相应作品、榜单和时间，不将个案当趋势。混合平台、日期、口径和续季的条目不直接相加排序。

在多个同口径可比样本足够时，按独立作品系列去重，分别报告样本数、日期跨度、排名/热度分布及集中度；不要把续季数量当独立IP数量。没有未上榜/低表现对照时只能描述入库样本，不能估计某标签的成功率，更不能把相关性说成标签导致热度。

### 内容潜力

给每项“强/中/弱”及一句具体理由，不用空泛星级：

1. **钩子可懂**：开局概述是否呈现一件看得懂又想追问的事？
2. **情绪够具体**：观众在替谁着急，等待什么回报？
3. **反差形成行动**：组合的新意是否会改变解题与人物关系？
4. **兑现可持续**：前三集能否给不同回报，同时引出新问题？
5. **差异可复述**：除了标签，有哪种独特策略、限制或关系？

### 制作适配

根据用户目标检查演员数量、场景复用、复杂接触/群像、变身与尺度切换、道具状态和声音负担。它决定同样条件下开发是否可行，不代表观众偏好。低成本也不能弥补无故事。

给出“优先开发/值得深化/暂缓”并说明主要理由、最弱项和怎样用开局概述及事件链检验。即使市场证据未知，也可以明确推荐内容更成立的一项，但应写“创作潜力判断”，不编造百分比或承诺必火。

## 五 抽卡输出

先给推荐排序，再按用户数量给具体候选卡；未指定时通常3–5张：

```markdown
本轮锁定：用户指定的全部标签
本轮可变：具体可抽槽位
推荐：C02优先，因为……；市场证据是历史快照/已核/未知。

### C01 暂定剧名
标签组合：4–6项
一句故事：主角、目标、阻力、策略、代价齐全
核心关系：双方各想要什么，冲突在哪
开局概述：具体发生的事件，不是“强冲突开场”；不写场标与连续对白
初期三次发展：各自的尝试、变化和回报，禁止相同事件换人；指定集数时可对应前三集事件
连载发动机：后续任务来自哪里
为何可能吸引人：最强两项和理由
同质化/逻辑短板：最弱项和修复办法
资料佐证：完整/邻近/组件分别多少个独立故事，代表source_id与P；原创部分是什么
市场证据：来源、日期、口径；无则未知；资料支持数不代替市场数据
制作适配：三路线中适合哪条、理由
取法依据：标签卡/规则ID；自创元素单独标记
```

快速抽卡可用比较表承载候选并展开最有必要的部分；用户要全量时全部展开。选定后把锁卡、故事规则与人物目标转入完整创意包，落地角色、特色、口头禅、热梗规划和大纲，不能丢掉抽卡承诺，也不生成正文。

## 六 用户示例如何真正落地

输入“黄毛＋穿越＋逆袭＋女频”：

- 保留4张锁卡；先把“女频”落实为围绕女性主体的欲望、选择、关系与兑现，不假装知道真实观众构成。
- “黄毛”可以是女主、搭档或对手，需明确职位与叙事作用；不能默认“他是主角，女人只负责崇拜”。
- 穿越要改变知识差和处境；逆袭要明确夺回什么。
- 可以扩出职业经营、假盟友成真同盟、女性自救与互救等不同方向，但这些是候选创作，不是已被市场验证的爆款组合。
- 若用户进一步指定“黄毛男主”，保留该约束并设计女性角色的能动性和关系承诺，不能擅改主角性别。

## 脑洞比较与检索补充

- 标签原词的窄查询0不等于上位机制不存在。先读tag_resolution与unmapped_constraints，再明确查受控标签或机制；例如“搞笑”窄词和T46喜剧荒诞不是同口径。展示两者，不自动把窄词的0改成上位数；未知猎奇不删。
- 对五个方向分别写匿名事件链、主角解法、对手反应、结构兑现。若多数仍“异常对象谈条件→主角支付或接责→建立新约定”，即使换了五套身体和职业，也要重构。改变因果方向、主体资格、观众所见与任务是否可被执行；别让每案都只走互相理解与议价。
- 用户连续要求更大胆时，至少两个候选必须改变“谁有行动权／何时选择产生结果／哪一层信息可信”中的一个，而非仅给新对象发言。用开局事件概述说明改动与结果；若需要一页解释，先缩到可懂的一次试验。
- 创意判断允许强点和弱点并存。给出为什么值得深化、哪里仍熟悉、哪个段落能检验；不得由两个JP码或一项radical标签宣称脑洞已达标。
- 复现抽卡需保存seed、全部参数、资料文件hash。资料改过，同seed可能换出不同类比来源。
